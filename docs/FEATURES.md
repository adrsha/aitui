| Image generation | ✅ | Image models (`gpt-image-*`, `dall-e-*`) are routed to the non-streaming `POST /v1/images/generations` endpoint instead of chat completions. The prompt includes the bounded user/assistant text conversation so facts gathered with a text model carry into a later image-model turn. Returned base64/URL images are decoded and normalized to PNG under `./aitui-images/img-<ts>.png`; completion is reported only after the file exists, with image-specific errors instead of misleading SSE errors. | Local models via llama.cpp | ✅ | Any OpenAI-compatible local server works unmodified — `scripts/llama-local.sh` wraps `llama-server` (`/v1/chat/completions`, SSE, `tools`, `/v1/models`) with sane CPU flags for a RAM-bound box. Point `endpoint` at `http://127.0.0.1:8080` (or `AITUI_ENDPOINT`), set model fields to the served alias, pick with `Ctrl-M`. Native tool-calling and the fenced fallback both work; `reasoning_content` streams for reasoning models; image generation simply 404s off the model list (no chat model routes there). |
| Generated follow-up replies | ✅ | Optional, default-off low-cost request after an ordinary completed assistant turn. The first suggestion appears as muted ghost text inside an empty composer; insert-mode `Tab` accepts it, while `Alt+1`–`Alt+3` still selects any of the generated alternatives. Without a visible suggestion, insert-mode `Tab` inserts a literal tab. Tool turns, mock/image replies, stale turns, and autonomous loops are excluded. Toggle with `:suggestions [on\|off]`; the configured suggestion model falls back to the active model. |

## Agentic workflow

| Feature | Status | Notes |
|---------|:------:|-------|
| Agent mode toggle (per session) | ✅ | `Ctrl-A` / `:agent`; default-on via config. |
| Categorized tool surface (5 tools) | ✅ | The model sees only `file_management`, `shell`, `web`, `interaction`, and `workflow`. Category calls choose an `action`; AiTUI resolves that action to an operation-level `ToolKind` before permissions/execution, so `read` and `delete` retain distinct risk and approval behavior without overwhelming the model with peer functions. |
| Web access (search / fetch / download) | ✅ | `web(action: search\|images\|reverse_image\|fetch\|download)` covers current-source search, reusable Wikimedia image discovery, reverse image search, URL→text fetch, and URL→local-file download. Ordinary HTTP search, fetch, image discovery, and downloads use installed `curl` first with `wget` fallback; local reverse-image uploads use Reqwest's blocking multipart client on the tool worker. No web operation nests an async runtime, and unexpected provider panics become failed tool results without invoking the process panic hook, printing over Ratatui, or leaving the alternate screen. URLs remain http(s)-only with a 20s timeout. |
| Filesystem management | ✅ | `file_management` actions cover read, whole-file write, exact unique edit, list, content search, mkdir, move/rename, recursive copy, and file/tree delete. Redundant append was removed; agents read then edit/write instead. |
| Tool invocation via `<tool>…</tool>` tags | ✅ | Fallback path (`:native off`, or auto after a tools-rejection). Tags replace the old ```` ```tool ```` fence so file content with its own ``` code fences can't close the call early; legacy fences still parse for old sessions. |
| **Native function-calling** | ✅ | D-017: sends `tools` schemas; the model returns structured `tool_calls` (streamed deltas accumulated by index in `api/client.rs`, synthesized into an internal `<tool>` block so render/execute/cut are unchanged). `api_messages(native)` translates stored turns → `assistant.tool_calls` + `role:"tool"` with `tool_call_id`. Config `api.native_tools` (default on) / `:native`; auto-falls back to fenced if the endpoint 400s on `tools`. |
| Rich decision requests | ✅ | `interaction(action: ask\|propose)` options wrap instead of clipping, scroll with selection, and show full selected text in a detail pane. Every option list includes **Custom response…** (`Tab` opens inline typing), while `e` opens the selected option in `$EDITOR` for a small user adjustment before choosing. |
| Adaptive step workflow | ✅ | Agent prompt requires full ordered analysis and one active `workflow(todo)` item at a time, with todo checks at each boundary. It asks only for genuine alternative paths, explains each path and feasibility, follows selected/custom path, and reports impossible selections immediately. |
| Numbered checklist subtasks | ✅ | `workflow(todo)` owns the parent task breakdown. The sticky panel is labeled `SUBTASKS`, renders stable one-based positions, and keeps the active progress frontier visible independently of child-agent execution state. |
| Dependency-aware parallel child agents | ✅ | The parent emits consecutive `workflow(action: agent)` calls for independent branches. Optional one-based `task_index` metadata links an agent to the main checklist subtask it owns. Children run as background tasks while the parent continues its own round; reports land in the conversation as tool messages and may be consumed mid-round. Each child gets a launch-order transcript entry that updates live and becomes a prominent completed/failed result immediately. Child agents inherit model/reasoning settings, can maintain a local `workflow(todo)` checklist, and may recursively delegate depth/batch-capped read-only child agents; the parent retains permissions, mutation, integration, conflict resolution, and final verification. Child lifetime combines a renewable progress lease, per-operation and absolute timeouts, and configurable soft/hard request budgets; reaching a soft bound forces one tool-free final synthesis so gathered evidence is not lost. Legacy `workflow(task)` calls remain readable but are not advertised. |
| Named agent registry | ✅ | D-023: `[agents.<name>]` in `config.toml` defines `description`, optional `model`/`role`, and a per-agent tool policy (`allow`/`deny` lists; empty allowlist = built-in read-only surface, `deny` wins). The `workflow(agent)` schema accepts an optional `agent` name that `start_task_batch` resolves — model override, role line, and policy apply to the child; unknown names fall back to the inline prompt. The agent-mode system prompt advertises configured agents (name, description, model) so the model can pick one; the subtask detail overlay shows the resolved agent name. |
| Permission prompts + risk levels | ✅ | Low/Medium/High. Manual resolution is the default. The prompt pins one highlighted rule sentence at the top with a full-line background: **allow/deny**, exact tool type or all tools, an independent **child directories included/current directory** selector, **any/requested/current/custom directory**, and **once/session/custom minutes/N matching requests/N total requests**. The statement wraps on narrow terminals, and the old `WHAT`/`WHY`/`HOW` section is removed. The request body shows only semantic details that make sense for each tool: edit gets aligned, vertically stacked `PATH`, `OLD`, and `NEW` cards; write gets `PATH` plus `CONTENT`; shell gets `COMMAND`; list/read/delete/mkdir get only `PATH`; move/copy get `FROM`/`TO`; and network/search tools get only relevant query, URL, path, or file-filter cards. Code-bearing cards use Tree-sitter highlighting, line numbers, a gutter, preserved indentation, and a horizontal scrollbar when content overflows; `Shift+Left/Right` moves the code viewport while `PgUp/PgDn` scrolls rows. `hjkl`/arrow keys move between phrases; Space opens the selector and chooses the highlighted value. Enter runs automated review, and Tab types custom paths/durations/counts inline. Scoped batch choices apply only to matching calls and re-prompt for the remainder. Deny decisions still accept an optional reason. |
| Auto-approve read-only tools | ✅ | Configurable; seeded as kind-scoped allow rules. |
| Per-session permission memory | ✅ | `PermissionMemory` holds `always_allow`/`always_deny` (kind) + scoped rules. Kind and directory filters compose; custom directory rules can optionally include child directories, deny wins, and timed/count-limited rules expire automatically. |
| Multi-round tool loop + loop guard | ✅ | Capped at 25 rounds. |
| Offline mock/test backend | ✅ | `api/mock.rs` turns messages into real tool calls (`read`, `write`, `edit`, `run`, `demo`, …) so the whole agent loop runs with no API. Auto-on when endpoint empty / `AITUI_MOCK` / `:mock`. |
| Streaming tool-call parsing | ✅ | Per-token `extract_tool_calls` on the partial drives two things: (1) in agent mode the stream is **cut** the moment a complete tool call appears (D-016) — no more runaway turns of redundant calls — and (2) read-only calls are **speculatively pre-run** (below). The `StreamingParser` state machine remains unused. |
| Speculative read-only tool pre-exec | ✅ | D-014: while a reply streams, complete `file_management` calls whose action resolves to `read`, `list`, or `search` are pre-run in the background (keyed by `hash(name,args)` in `spec_results`); `execute_tool` uses the cached result instantly. Never speculates writes/edits/deletes/shell/network. |
| Bounded parallel read waves | ✅ | D-022: consecutive already-authorized read/list/search and read-only web calls run concurrently in waves of up to eight. Permissions are still checked/consumed per call, mutations and interaction remain barriers, speculative hits fill their original slots, and results commit in source order. |
| Evidence-gated child verification | ✅ | `workflow(agent)` may supply explicit `checks` with `verification: replicate`. Two isolated replicas run concurrently; typed reports and local file citations are validated before voting, disagreement escalates to a third replica and then an independent verifier only when needed, and the parent receives one compact consensus/unresolved summary. |
| Unrestricted tool paths | ✅ | D-025: the session CWD is only the base for relative paths, not a containment boundary. Absolute paths, `..` traversal, and paths that follow symlinks outside the CWD are accepted by the executor after the normal permission flow. The former `config.agent.sandbox` option and executor path guards were removed. |
| Diff / content preview for edits/writes | ✅ | `file_management(edit)` renders a `-`/`+` diff at the call; write previews are collapsible (D-018). Changed rows use one thin `│` gutter; gutter and line number share red/green add/remove foregrounds, while the content area immediately to the right of the gutter fills through the transcript width with ANSI-8 and preserves syntax highlighting. On update, write/edit results emit a real old→new line diff (`line_diff`, common prefix/suffix stripped); tool-result output colours `+`/`-`/`@@` lines. New files report "Created", existing files "Updated". |
| Exact-edit unique-match safety | ✅ | `file_management(edit)` requires `old` to match verbatim exactly once; duplicate matches return their locations and require a larger disambiguating snippet. |
| Model-judged access policy | ✅ | Automated access review is opt-in; the default is manual resolution. `:review strict` / `:review lenient` enables review agents, while `:review off` restores manual prompts. `:access` stores a natural-language policy without silently enabling review. A fast judge model (`api.access_judge_model`, else the chat model) triages uncovered batches only when review is enabled; the safety floor still prompts and judge failures fall back to the human. |
| Autonomous loop mode | ✅ | `:loop` (editor form: GOAL/STOP/MAX) or `:loop <goal>` runs the agent toward a goal across turns without waiting for you. After each plain-reply turn it either continues (injecting a nudge) or stops at the `MAX` iteration cap; the model ends it by calling the `finish` tool once the STOP criteria are met. Per-session, persisted (`Session.loop_state`); `⟳ loop k/max` chip; Ctrl-C / `:loop stop` halts. |
